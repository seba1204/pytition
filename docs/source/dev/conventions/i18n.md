# Internationalization (i18n)

## General rules

### Use comments for translators

When a string requires additional context for translators, add a comment just above the string.
The comment has to start with `Translators:`.

::::{tab-set}
:::{tab-item} Python

```python
# Translators: This refers to the name of the user
_("Hello %(name)s") % {"name": name}
```

:::
:::{tab-item} Django templates

```html
{# Translators: This is the title of the page #}
<h1>{% trans "Welcome to Pytition" %}</h1>
```

:::
::::

## Python

### Do not concatenate strings

```python
from django.utils.translation import gettext as _

# ✅ Good
_("Hello %(name)s") % {"name": name}
# ❌ Bad
_(f"Hello {name}")
```

```{note}
⇉ Variable names are outside the `_(…)`.
This allows translators to better understand the context of the string.
```

### Never use `f-strings` for translatable strings

```python
from django.utils.translation import gettext as _
# ✅ Good
_("Hello %(name)s") % {"name": name}
# ❌ Bad
_(f"Hello {name}")
```

Indeed, `f-strings` are evaluated at runtime, which means the string is no longer translatable.

### Use named placeholders

When including variables in translatable strings, always use named placeholders instead of positional ones. This improves clarity for translators.

```python
# ✅ Good
_("Hello %(name)s") % {"name": name}
# ❌ Bad
_("Hello %s") % name
```

## Templates (Django)

### Prefer `transblock`

### Try to avoid html in translations

### Use `trimmed` on `transblock`

When using `transblock`, use the `trimmed` option to avoid unwanted whitespace.

```html
{% transblock trimmed %}
    This is a long text that
    spans multiple lines.
{% endtransblock %}
```
